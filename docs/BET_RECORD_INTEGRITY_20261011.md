# 下注记录完整性 + 赔率分层口径统一（2026-10-11）

## 背景

用户明确：**下注记录是预测系统的重要产出**，继续虚拟下注是为了留记录。
据此复查"记录本身是否可信"，发现两个实质缺口。

## 缺口 1：三套赔率分层口径不一致 → L3 亏损在账本里结构性不可见

修复前系统里有三套分层：

| 位置 | 分层 |
|---|---|
| `review/post_match.py::_odds_band`（账本） | <1.5 / 1.5-2.0 / 2.0-3.0 / 3.0+ |
| `review/ev_report.py::layer_of` | <1.5 / 1.5-1.8 / 1.8-2.2 / 2.2-3.0 / ≥3.0 |
| `config/strategy.json` favorite_band 闸门 | 边界 **1.8** |

账本的 `1.5-2.0` 桶**横跨**闸门边界 1.8，也横跨了 ev_report 的 L2/L3。

同一批注在两种口径下的表现：

    旧账本口径:
      1.0-1.5   n=299   -5.3%
      1.5-2.0   n=355  -13.6%    ← L2 与 L3 合并，闸门边界在桶内部
      2.0-3.0   n=294   -4.6%
      3.0+      n= 35  +12.7%

    新口径（闸门对齐）:
      L1 <1.5      n=299   -5.3%   t=-1.57
      L2 1.5-1.8   n=226  -14.6%   t=-2.70   ← 闸门边界
      L3 1.8-2.2   n=248  -12.7%   t=-2.02
      L4 2.2-3.0   n=175   +1.6%   t=+0.18
      L5 >=3.0     n= 35  +12.7%   t=+0.44

**这不是"不好看"，而是可发现性问题**：任何按 `odds_band` 做的账本聚合，
都不可能看出"odds 1.8-2.2 系统性亏损、而闸门恰好放开了它"。
这个缺口是靠 ev_report 的独立口径才发现的——如果账本能看见，本可早两个月发现。

## 缺口 2：`pnl=0.0` 无法区分"没下注"和"下了没中"

账本此前只有 `hit` / `pnl`。`hit=False` + `pnl=0.0` 可能是：

- 闸门禁投，正确地没下注
- edge 闸门 / 置信过滤，没下注
- 下了注但没中（那 pnl 应该是 −stake，不是 0）

三者在评估里含义完全不同，但记录上无法区分。

## 改动

### engine/odds_bands.py（新增，分层单一真源）

`layer_of` / `layer_short` / `gate_blocked_layer_names`。
边界 1.5 / 1.8 / 2.2 / 3.0 **与 favorite_band 闸门对齐**。
禁投层集合由配置推导，不硬编码。

`review/post_match.py::_odds_band` 与 `review/ev_report.py::layer_of`
均改为委派至此，删掉各自那份。

### engine/review/post_match.py（下注决策可审计）

`MatchReview` 新增字段：

| 字段 | 含义 |
|---|---|
| `odds_used` | 实际所下注的赔率 |
| `odds_layer` | 闸门对齐的 L1-L5 |
| `bet_sel` | 实际所下注的玩法（hcap_away / ttg_1 / 1-0 / home…） |
| `stake_planned` | 该场实际计划注额（0 = 未出注） |
| `gate_blocked` | 是否被 favorite_band 禁投 |

结算时载入 `ticket_plan.json`，把注额与所下玩法关联进账本
（串关注额按腿数摊销到每条腿）。

### 一个实现陷阱（已处理，值得记）

第一版按**1X2 主推方向**判闸门，实测立刻出错：

    2026-09-01 周二007
      1X2 主推 = 主胜 1.46   → L1 → 应禁投
      实际出注 = 让球客胜 2.28 → L4 → 应放行，注额 205.3

按 1X2 主推判会把一笔**已放行**的注记成"禁投"。
改为**按实际注的赔率/玩法判定**后，禁投计数从 4 降到 2
（另外 2 场实际是通过让球/总进球玩法出注的）。

教训：账户口径必须与执行口径一致。执行层出的是"玩法 + 赔率"，
评估层若按"1X2 主推"归类，两边就对不上——这与项目里
`ev_report` 与 `favorite_band` 的历史口径脱节是同一类错误。

## 验证

`tests/test_odds_bands_and_bet_record.py` 8 个 —— 分层边界 + 实际注覆盖主推。

全套 `pytest tests/ -q` = **232 passed**（原 224），`ruff check --select F` 干净。

## 仍然没动的：L3 闸门边界要不要移

**结论：不移。证据不支持。**

L3 全样本 n=248 / ROI −12.7% / t=−2.02 看似显著，但稳健性检查不通过：

| 切分 | n | ROI | t | 判定 |
|---|---|---|---|---|
| 前半（较早） | 124 | −10.2% | −1.14 | 不显著 |
| 后半（近 30 天） | 124 | −15.2% | −1.71 | 不显著 |

按联赛也全部不显著，且有正收益联赛（日职 +9.8% n=18、西甲 +1.1% n=21）。

而且把 L3 全禁之后，剩下 L4+L5 = n=210 / ROI **+3.4% / t=+0.39**，
同样不显著——**移边界并不能得到一个"显著盈利"的下注口径**，
只是移走了一段边缘亏损。

在抽水 12.1% vs 模型相对优势 0.64% 的前提下，任何单层 ROI 检验
都很难达到显著（要检出需 n 数千）。所以正确的动作不是调边界，
而是继续积累记录，让分层证据随样本增长自动显现。
