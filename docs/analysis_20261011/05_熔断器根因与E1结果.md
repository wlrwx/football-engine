## 一、熔断器为什么没触发 —— 完整根因

答案是**三层独立缺陷叠加**，任何一层单独存在都足以让它失效。三层同时存在，
所以熔断器自始至终完全惰性。

### 缺陷 1：乘数被硬编码丢弃（2026-07-23 起）

`engine/main.py`：

```python
# 第 859 行：熔断算出来了
breaker_mult = breaker.get_multiplier(actual_bankroll)
# 第 863 行：也打印了
print(f"...multiplier={breaker_mult}")

# 第 908 行：然后被硬编码覆盖
effective_mult = 1.0  # 虚拟投注不降注
allocator = ThreeTicketAllocator(
    bankroll=actual_bankroll,
    breaker_multiplier=effective_mult,   # ← 永远是 1.0
)
```

引入这个改动的提交：

```
f93821560  2026-07-23  fix: 移除虚拟投注熔断限制
```

该提交同时删掉了停注分支和置信度收紧：
```diff
-    if breaker_mult == 0:
-        print("  ⚠ 熔断停注中，生成观察计划（不实际投注）")
+    # 虚拟投注：不熔断，始终正常投注
-    conf_threshold = breaker.get_confidence_threshold()
+    conf_threshold = 0  # 虚拟投注不限制置信度
-    effective_mult = breaker_mult * min(1.0, risk_budget["cushion_ratio"] * 3)
+    effective_mult = 1.0  # 虚拟投注不降注
```

**熔断器仍在计算、仍在打印，但它的输出从不参与决策。**

### 缺陷 2：熔断器只读三个桶，看不到真正动钱的注

`main.py` 结算段：

```python
ticket_map = {}
for grp in ("stable", "value", "lottery"):     # ← 没有 parlay / score_parlay
    for s in ticket_data.get(grp, []):
```

而 `ticket_plan.json` 实际有五个桶，分布：

| 桶 | 累计条目 |
|---|---|
| stable | 11 |
| value | 47 |
| lottery | 31 |
| **parlay** | **119** |
| **score_parlay** | **195** |
| 合计 | 403 |

**占 78% 的 parlay / score_parlay 对熔断器完全不可见。**
而 07-25 ~ 07-27 资金从 10,000 冲到 349,134（单日 +214%），
正是串关赢钱造成的 —— 那批注熔断器一条都没看到。

### 缺陷 3：喂进去的注额恒为 0，日/周止损永远不成立

熔断的日/周止损条件是：

```python
if s.daily_date == today and s.daily_pnl < 0:      # 要求 daily_pnl < 0
    ...
if s.weekly_pnl < 0:                                # 要求 weekly_pnl < 0
```

而 `pnl` 由 `_stake * (_odds - 1)` 或 `-_stake` 累加。
shadow 模式下 stable/value/lottery 三桶的 stake 全为 0 → **pnl 恒为 0.0**。

实测 `data/state/circuit_breaker.json`：

```
history: 200 条
  tier 分布          : 全部为 0（tier>0 的记录数 = 0）
  halted=True 次数   : 0
  每条记录 pnl       : 0.0
```

**熔断器的两个硬止损（日亏 5%、周亏 12%）从未有过触发条件成立。**

### 叠加后的实际效果

| 时间 | 发生了什么 |
|---|---|
| 07-19 / 07-20 / 07-22 | `breaker_multiplier = 0.9`（连败阶梯生效了） |
| **07-23** | 提交 f93821560 移除熔断 → multiplier 变 1.0 |
| 07-25 ~ 07-27 | 串关赢钱，资金 10,000 → 349,134 |
| 07-28 ~ 08-03 | 资金 349,134 → 85,488（熔断全程关闭） |
| 08-04 | **资金重置到 5,000** |
| 08-04 ~ 10-11 | 资金 5,000 → 3,870.79，熔断始终 tier=0 |

### 另一处独立的设计问题

即使前三个都修了，熔断器的触发条件本身也够不上这个场景：

- 触发靠**连败数**（3/6/12/15），不是**回撤**
- 恢复只要**连赢 2 场**（`recovery_streak = 2`）
- 在胜负混杂的真实序列里，连败 3 次极少发生；一旦触发也只降注 50%

**它没有"距峰值回撤超过 X%"这种触发条件** —— 而 07-27 之后的暴跌正是回撤驱动、不是连败驱动的。

## 二、订正：资金曲线的正确读法

我上一轮说的「自峰值 −98.9%」**是错的**，因为跨越了重置点。正确读法：

```
2026-07-19      10,000.00
2026-07-25      24,040.00   (+140%)   ← 串关
2026-07-26     111,235.59   (+363%)   ← 串关
2026-07-27     349,134.20   (+214%)   ← 峰值
2026-07-28     237,502.86   (-32%)
2026-07-29     209,572.12   (-12%)
2026-07-31     129,742.02   (-38%)
2026-08-03      85,488.15   (-28%)
2026-08-04       5,000.00   (-94%)   ← 重置点
2026-08-09       4,986.40
   ... 稳步下行 ...
2026-09-03       3,673.29
2026-09-15       3,870.79
```

正确的两个数字：

| 区间 | 变化 |
|---|---|
| 旧口径 07-19 → 08-03 | 10,000 → 85,488，**峰值 349,134 时 −75.5%** |
| **重置后 08-04 → 10-11** | 5,000 → 3,870.79，**−22.6%** |

CPPI 的 `floor = 3500`，当前 3,870.79 在地板之上，说明 CPPI 的地板保护是生效的
（09-03 触底 3,673 后小幅回升）。

**注意重置本身是个需要解释的事**：08-04 从 85,488 掉到 5,000，
系统里没有任何一处记录了这次重置的原因。这和上一条报告里的「两套记账互不勾稽」是同一个问题的两面。

## 三、E1 实验结果：市场修正有无增量信息

### 设计

```
logits = log(p_close) + W·x + b
p      = softmax(logits)
```

**市场收盘价是基底而不是特征之一** —— `W=0` 时精确退化为 `p_close`，
所以 `W` 学到的就是「市场修正里未被收盘价吸收的那部分」。
（这一点我第一版写错了：最初只用 `X` 做 softmax，等于让模型从零预测，
特征里根本没有市场价格，测的是"能不能替代市场"而不是"修正有无增量"。）

特征 23 维：市场修正 3 维 + 修正强度 + 净方向移动 + 跨公司分歧 + 分歧对数
+ 亚盘线 + 大小球线 + 14 联赛 one-hot。

严格时间切分，27 次重拟合，31,058 条配对预测，2019-07 ~ 2026-08。

### 结果：E1 未通过

| 指标 | baseline（市场收盘） | challenger（市场修正） | Δ | t |
|---|---|---|---|---|
| logloss | 0.97983 | 0.97968 | −0.00015 | −1.28 **不显著** |
| brier | 0.58366 | 0.58360 | −0.00006 | −0.80 **不显著** |
| rps | 0.19816 | 0.19811 | −0.00004 | −1.47 **不显著** |

决策层（按收盘赔率下注，盲买成本 −5.3%）：

| 阈值 | 注数 | ROI | PnL |
|---|---|---|---|
| 0.00 | 44,895 | **−5.06%** | −2,272.4 |
| 0.02 | 461 | −3.77% | −17.4 |
| 0.05 | 5 | +13.40% | +0.7 |

**判定：E1 未通过 —— 市场收盘价已经把自身修正吸收干净了。**

阈值 0 那行是最说明问题的：模型下了 44,895 注，ROI −5.06%，
和闭眼盲买的 −5.3% **几乎一模一样**。它既没赢过抽水，也没输得更惨，
只是把抽水付了 44,895 次。

阈值 0.05 的 +13.40% 是 n=5，没有意义。

### 两个实验合起来的结论

| 实验 | 检验对象 | 结果 |
|---|---|---|
| E0 | 纯球队实力模型（DC）能否优于市场 | **显著更差**，Brier Δ=+0.02018，t=+34.74，21/21 联赛 FDR 显著 |
| E1 | 市场自身的修正能否优于市场收盘价 | **与市场无差异**，Δ=−0.00006，t=−0.80，不显著 |

**两个方向都撞到同一堵墙：去水收盘价是不可逾越的基准。**

- E0 说明「球队实力」这条路走不通
- E1 说明「预测市场会怎么动」这条路也走不通

所以那个 6.25% 的模型权重槽，**现有数据里没有任何候选能挣到它**。
`λ=0`（纯市场）不是一个失败选项，它是一个有 31,058 / 71,774 两组独立证据支持的结论。

### 诚实的边界

E1 测的是「已知收盘价的前提下，修正还有没有增量」。
它**不能**回答「在收盘之前、盘中能否捕捉到修正」——
那需要盘中高频快照，而历史数据只有开盘/收盘两个时点。

实盘侧的对应资产是 `data/state/odds_series/` 的 871 个文件，
但实测平均每场只有 **3.3 个快照**，158 场只有 1 个。
要做盘中实验，先得把快照密度提上去，否则样本量撑不住任何结论。

## 四、建议的修复顺序

| # | 项 | 性质 |
|---|---|---|
| 1 | 熔断器 `effective_mult` 接回 `breaker_mult` | 一行，但要先决定 shadow 模式下是否降注 |
| 2 | 熔断器补 `parlay` / `score_parlay` 两个桶 | 缺陷 2 |
| 3 | 熔断器加「距峰值回撤」触发条件 | 补设计缺口，与 1/2 独立 |
| 4 | 08-04 那次资金重置补记录 | 现在完全查不到原因 |
| 5 | 串关注额与 1X2 分账 | 349,134 的尖峰全是串关，混在一起看资金曲线没有意义 |
| 6 | odds_series 快照密度 | 盘中实验的前置 |

前三项做完，熔断器才第一次具备实际作用能力 —— 在此之前，
`ticket_plan.bankroll` 那条曲线不能作为任何决策依据。
