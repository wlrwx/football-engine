# 实验登记表（EXPERIMENTS）

> 建立于 2026-10-11。**开工前登记，跑完不许改判定标准。**

## 为什么需要这张表

workbuddy 的建议里有一条成立且被低估了：

> 如果 agent-auditor 跑 50 个诊断、agent-X 跑 50 个假设，各取最好的那个报上来，
> 多重比较照样骗过去。

`PROPOSAL.md`（workbuddy 方案）管的是**单次实验**的预注册；
这张表管的是**跨 agent 的组合级**多重比较。两者互补，缺一不可。

同样的道理，qwen 自己给联赛异质性标了 FDR 警告，却没把它用在自己的 agent 组合上。

## 登记规则

1. 任何实验开工前在下面登记一行：假设 / 分支 / 主指标 / 判定日 / 最小样本量
2. **判定标准写死后不许改**。看到 p=0.06 就把阈值改成 0.1 的实验一律作废
3. 组合级结论必须过 BH-FDR（α=0.10），单实验 p 值不能直接当结论
4. 已登记但失败/中止的实验**保留行、标注结果**，不得删除——失败结论和成功结论价值相同
5. `docs/analysis_20261011/` 下的分析文档是对外可审计的推理记录，改结论必须同步更新

## E2：跨盘口不一致（2026-10-11）

### 结论

**未通过。** 33,058 场、66,116 注亚盘 + 66,115 注大小球，两个盘口都没有可提取的
跨盘口矛盾。

| 盘口 | 去均值回归斜率 | 十分位 Spearman | 最高十分位 ROI |
|---|---|---|---|
| 亚盘 | slope=+0.3352, **t=+2.97**, R²=0.00013 | 0.491（非单调） | **−1.79%**, t=−1.69 |
| 大小球 | slope=−0.0402, t=−1.81, R²=0.00005 | −0.212 | **−9.48%**, t=−6.96 |

亚盘那个 t=+2.97 是**假阳性**，被十分位单调性检验拦下：
它的十分位 ROI 是 −5.82/−5.28/−3.77/−2.77/−1.44/−4.98/−2.82/−3.64/−4.94/−1.79，
既非单调也不为正，斜率几乎全由信号低到 −2.09 的离群尾巴撑着。

大小球方向**相反**：信号最高十分位（市场给的赔率最厚）的命中率只有 40.9%，
是全表最差。市场给厚价是因为它认为该结果不太可能，而它是对的。

因此判定改为三重条件同时成立才算信号：
**斜率 t 显著 + 十分位 ROI 与分位序号强正相关（Spearman>0.7）+ 最高十分位 ROI 显著为正**。
只看单一 OLS 斜率会给出假阳性 —— 这条已写进 `cross_market.py` 的 `robustness`。

### 两条方法论修正（比结论本身更重要）

**1. 对有走盘的盘口，不能用"去水概率"和模型概率做差。**

亚盘赔付不是二值的：赢了拿 O、走盘退本、输了没。对 1 单位本金，公平赔率满足

    w·O + p = 1        w = 赢的注资份额，p = 走盘的注资份额
    ⟹ O_fair = (1 − p) / w

而 `devig2` 把两路赔率归一化得到的那个"概率"，对有走盘的盘口并不等于赢盘概率。
实测 `line=−1.00`：两路去水后恒为 0.5005（中位 0.5000），
但实际赢注资份额只有 0.3795（走盘率 26.9%）—— 差的正是走盘那一块。

初版用去水概率做差，AH 信号均值因此出现 **−0.0679** 的系统性偏差，
看起来像"市场大幅高估主队"，实际是自己的口径问题。
改用 `O_fair = (1−p)/w` 后信号才有可比性。

**2. 独立泊松拟合 1X2 之后，系统性低估总进球约 9%。**

实测 8,000 场：

| 指标 | 值 |
|---|---|
| 模型反解出的 λ_h+λ_a | **2.420** |
| 实际总进球均值 | **2.672** |
| 模型 P(over 2.5) | **0.4309** |
| 市场去水 P(over 2.5) | 0.5105 |
| 实际 P(over 2.5) | **0.5050** |

市场是对的，模型错了。独立泊松是 2 参数族，拟合 1X2 三个概率后
无法还原真实的进球联合分布。这不是市场无效率，是**模型设定误差**，
但它会给信号带来一个巨大的常数分量，直接按 |信号| 分桶必然把
设定误差误读成错价。所以必须**按让球线分组去均值**后再判断。

### 实现过程中修掉的静默错误（全部是"看起来能跑但结果是错的"）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | `devig()` 只支持三路 | 大小球两路去水静默失败 |
| 2 | `h, a` 只在 AH 分支赋值 | O/U 分支变量未定义 |
| 3 | λ 反解用乘性不动点迭代 | 平局率偏低时两 λ 一起塌到下界 0.05 |
| 4 | 解析梯度里 `I1 = (ph-pm).sum()` | 归一化 pmf 和恒为 1 → 梯度全零 → 优化器原地不动 |
| 5 | `resid` 返回三维向量而 `minimize` 要标量 | 每次抛 ValueError 被 `except` 吞掉，**33,158 场全部静默回退到 λ=(1.3,1.3)**，网格真值 (2.7,0.8) 差 5 倍 |
| 6 | 残差公式对边际求和恒等于 1 | 应为三角区域求和 `j[h>a]` |
| 7 | 亚盘用欧式三路结算 | 信号出现 ~16pp 系统偏差 |
| 8 | 亚盘走盘按输（−1）计 | 系统性做空"半赢半走" |
| 9 | 半赢按幅度阈值判成走盘 | 半盘线下平局球（margin=0.5）是赢不是走盘 |
| 10 | `ah_units` 把净胜球差当成已加让球线的 margin | **完全忽略让球线**，同一 λ 下所有让球线期望收益恒等 |
| 11 | ROI 写成 `odds*u` | 把本金算成利润，ROI 虚高一倍 |

第 5 和第 10 条最危险：输出都"看起来正常"（λ 合理、概率和为 1、注数与胜率齐整），
但毫无信息量。两者都靠**不变式测试**才暴露，见
`tests/test_cross_market_settlement.py`。

核心不变式：`E[u] ≡ p_home − p_away`（把 `ah_units` 在同一比分 pmf 上求期望，
必须等于 `ah_probs` 给的赢/输注资份额之差）。102 组合实测偏差 ≤1e-12。

亚盘符号约定也做了实证确认：football-data.co.uk 的 `AHCh` 是**加在主队进球上的
让球数**，强主队为负、弱主队为正（主胜赔率<1.6 的强主队均值 −1.473，
>3.0 的弱主队 +0.680）。独立佐证：按此约定平注 ROI 为主队 −4.89% / 客队 −2.56%，
与亚盘 overround 4.59% 吻合；若把 line 取反，ROI 变成 **+15.88%** ——
那种"稳定赚钱"只可能是符号搞错了。


## E3：决策层闸门可达性（2026-10-12）

### 结论：不能 —— 而且**理由不是阈值太大**

E0/E1/E2 之后最自然的问题：既然模型不行、闸门又调不动，那是不是**阈值没调对**？
E3 的答案是不能，而关键在于两个数字必须**一起读**：

| 口径 | EV 闸门所需权重中位 | 配置值 0.10 够得着吗 |
|---|---|---|
| 假设模型**完全正确**（p_dc=1，理论最优） | **0.0638** | 够得着，可达 **72.33%** 的选项 |
| 换**实测模型**（账本 873 行真实 p_dc−p_fair） | **0.5772** | **只有 4.8%** 的场次够得着 |

即 `model_weight=0.10` 相对 12.1% 抽水**本身并不小**，抽水才是主要门槛；
真正锁死闸门的是**模型质量** —— 与 E0 的 Brier Δ=+0.02018（t=+34.74）一致。
账本实测 `p_dc − p_fair` 中位仅 **+0.0343**，且 **40.2%** 的场次里模型更差。

所以**调 `min_ev` / `min_edge` 救不回来**：降阈值只是把不可达的闸门强行打开，
让系统去下负期望的注，不产生正 EV。

### 数学

```python
# engine/strategy/kelly.py
market_prob = 1.0 / odds            # 原始赔率倒数，含抽水
edge = model_prob - market_prob
ev   = model_prob * odds - 1.0
if edge < self.min_probability_edge or ev < self.min_ev: continue
```

设 `p_system = w·p_dc + (1−w)·p_fair`、`odds = 1/(p_fair·(1+v))`，
EV 闸门要求 `p_system·odds ≥ 1 + min_ev`，解出

```
w ≥ p_fair · [(1+min_ev)(1+v) − 1] / (p_dc − p_fair)
```

`v=0.121`、`min_ev=0.03` 时方括号 = **0.1546**。模型不如市场时所需权重为**负**
—— 要反向跟随模型才可能过关，那不是好消息。

### 附带发现：`min_probability_edge` 参数名与行为不符

`kelly.py` 拿 `1/odds`（**含 12.1% 抽水**）当"市场怎么看"，而系统其它所有模块 ——
`engine/review/clv.py`（自带 `devig()`）、`scripts/upgrade_tracker.py`、
`engine/review/post_match.py`、账本的 `market_fair` —— 用的都是**去水**概率。

于是该参数实际强制的是 `p_model − p_fair ≥ 0.03 + p_fair·v`：

| p_fair | 参数名 | 实际门槛 | 倍数 |
|---|---|---|---|
| 0.10 | 0.03 | 0.0421 | 1.40× |
| 0.20 | 0.03 | 0.0542 | 1.81× |
| 0.30 | 0.03 | 0.0663 | 2.21× |
| 0.40 | 0.03 | 0.0784 | **2.61×** |

**本 PR 不改这个行为** —— 改成去水口径会把门槛放宽 1.4~2.6 倍，
而 E0~E2 全部为负的情况下放宽只会增加亏损注。这是需要人拍板的取舍。
`tests/test_gate_reachability.py` 里没有锁死现状，是有意的：
真要改时应当连同 E3 结论一起改，而不是悄悄漂移。

## E4：换博彩公司的收益（2026-10-12）

### 结论：部分收益，但翻不了正

CLV 报告首跑 **NEGATIVE_CLV**（下注 vs 去水收盘 −12.45%，报告点名"含竞彩 ~8% 水位逆风"）。
E0~E3 分别证明：模型无 edge、市场修正无增量、跨盘口无矛盾、闸门调不动。
剩下唯一没被量化的杠杆就是**抽水本身**。

`football_data` 里本来就有 **Pinnacle**（`PSCH/PSCD/PSCA`，67,613 行）与 B365、Avg
的同期收盘价，不必等 SportMonks 客户端就能直接量化。

按 Pinnacle 去水概率选最可能结果，按各盘实际赔率下注（28,049 场，收盘口径）：

| 盘口 | overround | 抽水 | 注数 | ROI | t |
|---|---|---|---|---|---|
| **Pinnacle** | 1.0302 | **3.02%** | 28,049 | **−1.32%** | −2.20 |
| Avg | 1.0666 | 6.66% | 27,968 | −3.49% | −5.94 |
| B365 | 1.0710 | 7.10% | 618 | +0.47% | +0.12（样本太少） |

**换到平博 = 每千注多赚 21.7 元。** 差值 2.17pp 与抽水差（6.66% → 3.02%，3.64pp）
同量级同方向 —— 这就是抽水差本身，不是神秘 alpha。

**但最锐利的平博本身仍是 −1.32%。** 与 E0~E3 完全一致：

> **没有 edge 时，选哪家博彩公司只能在负数之间做选择，不能把负数变成正数。**

对竞彩用户的意义是**外推**而非实测：本数据集是欧洲盘（Avg 收盘抽水 6.66%），
不含竞彩；竞彩实测抽水 12.1%，切到平博的潜在收益**大于**这里实测的 2.2pp。
但按结论方向外推，翻正仍需额外 ~1.3pp 以上的**真实 edge**，换个盘口不够。

### 数据覆盖限制：开收盘与比分不同源

本实验只能比**收盘**，开盘列（`PSH/PSD/PSA`、`B365H/...`）样本为 0。

（另注：早先量到的 Avg 抽水 5.85% 是**开盘** `AvgH` 口径，
与这里 6.66% 的**收盘** `AvgCH` 口径不是一回事，别混用。）

## E5：联赛级参数接线（2026-10-14）

### 结论：否——**不可检出**，而不是"试了没用"

这是 E0~E4 之外唯一一条还没被证据处理的线索。
`engine/learning/league_params.py` 里存着每个联赛的
`base_goals` / `home_adv_weight` / `market_blend_weight` 存档，
但三个 getter `get_base_goals()`（:347）/ `get_home_adv()`（:351）/
`get_market_blend()`（:355）**全仓无调用方** ——
`engine/main.py:268-269` 构造 `DixonColesConfig` 时只用
`config/prediction.json` 的全局值（`base_goals 1.35` /
`home_adv_weight 1.0` / `market_blend_weight 0.28`）。
"给欧冠接上 `home_adv_weight 0.90`" 看着是件低成本的好事，
所以值得单独测一次，而不是凭感觉接。

**测法**：48 场 v2 账本（2026-10-11/12/13，账本里唯一带
`elo/attack/defense/form` 快照的三天——该快照 2026-10-09 才加，
`main.py:758-770`），逐场重算 DC + fuse：
`global` 臂用全局参数，`league` 臂用该联赛存档参数。

| 臂 | Brier |
|---|---|
| global（= 现状） | 0.56127 |
| league（存档参数接线） | 0.56146 |
| stored `final_prob`（参考基线） | 0.56019 |

**Δ=+0.000191，t=+0.44，sd=0.00301** —— 方向还是"接了更差"，
但真正的问题是**这个数字根本测不出来**：

```
n(557 场的检测下限) ≈ 1.96 × 0.15 / √557 ≈ 0.0125
实测效应                                    ≈ 0.0002
比值                                        ≈ 20–50×
检出所需样本量                              ≈ 952 场
按当前速率（约 2.5 个月 300 场 v2 结算）     ≈ 3.2 年
```

### 为什么效应这么小：作用链被稀释两次

1. `market_blend_weight` 0.28→0.32 只改 `model_raw` 里的市场混合比例。
   `dixon_coles.py:77-80` 是线性混合，残差 `model−market` 均值仅 0.0417，
   所以对 `model_raw[home]` 的位移约 **0.0017**
2. `model_raw` 再进 fusion 时，champion 权重 `0.05/0.75/0.20` 因 DJYY 死源
   重新归一化 → **有效 model 权重 0.0625** → 到 `final_prob` 只剩约 **0.0001**
3. `home_adv_weight` 0.90 vs 1.0 只让 `log_home` 变 −0.01 → xG 变 0.990（1% 量级），
   且 `dixon_coles.py:132/142` 里它**只进 `log_home` 不进 `log_away`**，进一步减半

即：**联赛参数改的是 model 层，而 model 层在最终输出里只占 6.25%，
且这 6.25% 已被 E0 证明显著为负。** 在一个已被判无效的流上做微调。

### 与 E3 的关系：同性质，不同死法

| 实验 | 死因 |
|---|---|
| E3 | 闸门够不着 —— 模型**质量**锁死了可达性（需要 0.577，只有 4.8% 够得着） |
| E5 | 接线无效 —— 模型**权重**只有 6.25%，把效应稀释到检测下限以下 |

E3 是"模型不够好所以用不上"，E5 是"模型占的比重太小所以调了也看不见"。
两条共同指向：**在 `model_weight` 显著上升之前，任何模型层调参都没有统计意义。**
而 `model_weight` 要上升，需要模型质量先改善——鸡生蛋问题，
现有数据里没有任何候选能挣到这个权重槽（见 E0~E4 汇总）。

### 由此产生的三个明确决定

1. **不接线**。`data/state/league_params.json["欧冠"]` 的
   `home_adv_weight 0.9` / `market_blend_weight 0.1` 保持未接线。
   已在三个 getter 处加注释说明"为何保持未接线"，防止后来者
   以为漏接了而顺手接上
2. **不把联赛参数接到 fusion 层**（如联赛级 `model_weight`）——
   那是预测层新机制，需独立预注册，不在 E5 范围
3. **重开此实验的前提**：`model_weight` 有效值显著上升，或
   回放保真度问题解决（48 场之外还有 509 场缺评级快照，
   且当前 `team_ratings.json` 是赛后值，回放忠实率仅 13.9% 误差<0.05）

### 顺带修正的两个认知

- `league_params.json["欧冠"].market_blend_weight` 存档值是 **0.1**，
  不是 `LEAGUE_PRIORS`（`league_params.py:121`）里的先验 **0.32** ——
  两处不同值，别混用
- "要给引擎加欧冠预测"这个说法不成立：10-13/10-14 已分别预测
  8/7 场欧冠，管线一直在跑。欧冠的真实缺口是**挑战池匹配**与
  **联赛参数接线**，不是"能不能预测"（详见
  `docs/RETROSPECTIVE_20261013_NIGHT.md` 的修正记录）

### 代码侧已修（PR#13）

  （被拦截不是限流，重试无意义）；5xx 才重试

### 2026-10-22 归因：Worker 出口被整体挑战，A/B 都不是解

部署带重试与浏览器头的 Worker 后，CI 仍然是 403。探针头
`x-proxy-attempts: 3` 证明重试确实执行了、但三次全失败。Worker 侧诊断
（一次调用内顺序探测，`cf-mitigated`/`cf-ray` 随响应返回）：

| 探测 | 结果 |
|---|---|
| 首页 GET（浏览器导航头） | 403 `cf-mitigated: challenge` |
| API GET ×3（JSON 头） | 403，间隔 1s，耗时 2–14ms |
| 先取首页 cookie 再请求 API | 首页 403、无 Set-Cookie，API 仍 403 |
| Worker colo | ORD（此前 IAD/SJC/DFW 同样 403） |

挑战页在 2–14ms 内返回，说明不是概率性 bot 评分，而是上游按出口 IP/ASN
（或 Cloudflare 对 Worker 子请求的标记）**整体拒绝**；header、cookie、
退避重试都不改变结果。此前偶尔看到的 200 是 Worker 响应 `max-age=60`
被边缘缓存后的假象（同一 URL 一分钟内的重复探测）。

因此：
- **方案 A（Worker key）**：key 解决的是"别人白嫖 Worker"，不是上游挑战，无效；
- **方案 B（放行 GitHub IP 段）**：Worker 出口不是 GitHub IP，而是 Cloudflare
  AS13335，规则打不到；CI 直连仍是 GitHub IP，但无权改对端 WAF。
- **实际修复：把抓取放回本机住宅网络**。`njstats_duty.py` 每轮检查
  `data/djyy_matches.json` 的 `extracted_at`，超过 10h 就直连抓取并提交；
  CI 每轮仍会尝试，失败时保留仓库快照（`fetch_djyy_ssr.py` 已加
  "半程失败不写盘"）。2026-10-22 实测本机直连：200 场、200 场带
  Pinnacle 赔率、200/200 有模型概率。
- 预测侧补位：`engine/main.py` 在实时源缺失时把快照的 `djyy_model_prob`
  传给 fusion（日志打 `DJYY 概率补位: n/N 场`），否则快照只能补 xG/赔率，
  `djyy_weight` 仍会被重新归一化掉。

残留风险：笔记本连续 10h 以上不在线时快照会变旧。预测日志会打「快照龄 Nh」，
超阈值有 ⚠；`djyy_status.json` 在补位发生时写 `snapshot_probs/snapshot_age_h`，
health-check 只在「实时被拦**且**无补位」时 error，补位生效降为 warning。
自检的通道存活率也改看 `djyy_model_prob`（实时或快照），不再只看
`djyy_enriched` 实时标志（后者在补位生效时仍会误报 <50%）。

xG：API v2 的 fixtures 响应不含赛前 xG（2026-10-22 快照 0/200），
`DJYYSSRSource` 的 xG 字段保留但恒空；第三通道靠 `djyy_model_prob`，
xG 缺失不阻塞。**不需要再配 `DJYY_KEY`，也不需要给 Worker 加白名单。**
